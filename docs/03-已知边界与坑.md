# 已知边界与坑

这份文档记录**实际踩过的坑**。大部分不是「代码写错了」，而是
**「验证方式本身在骗人」**——后者隐蔽得多，也更值得写下来。

## 一、`report-html` 转换器的边界

### 支持的语法

ATX 标题 `#`–`######`、围栏代码块、水平线、**嵌套**有序/无序列表 + 松散列表 + 缩进续行、
**嵌套**引用块、表格（含 `:---:` 对齐与单元格内 `<br>`）、
粗体/斜体/删除线/行内代码/反斜杠转义、`[文字](url)` 与裸 URL 自动链接。

特有约定：`[X9]` 形式引用 ID 自动变成跳转锚点；附录里 `- X9 / 标题 / …` 形式的条目
自动获得 `id="src-X9"` 目标。

### 不支持（会原样保留）

setext 标题（`===` 下划线式）、引用式链接、脚注、任务列表、HTML 块、定义列表。

### 边界

| 项 | 说明 |
|---|---|
| **图片降级成链接** | 为保证输出自包含，`![alt](url)` 不渲染远程图片，改为链接 |
| **字面量 `**` 会误判** | 正文若真有字面量 `**`，会被「残留 Markdown」自检拦下。用 `&#42;` 或改写措辞 |
| **只做静态渲染** | 无交互、无搜索框 |
| **需要 python3** | 纯标准库，无第三方包 |

### ⚠️ headless Chrome 截图不响应锚点跳转

用 `--screenshot file:///...#h16` 想验证某个锚点的渲染，**拿到的是页面顶部**——
headless 模式下锚点跳转不生效。

可行的替代：
- 把目标片段单独抽出来配同一份 CSS 成一个独立 HTML 再截图
- 量化探针改用 `--dump-dom --virtual-time-budget=2000`

## 二、数据判断的坑

### ⚠️ 口径分歧**不要取平均**

同一指标多来源冲突时，取平均是**最糟的处理**——它伪造了一个不存在的精确值。

真实例子（`examples/lithography_深度研报_2026-10-09.md` 里就有三处）：

| 指标 | 来源 A | 来源 B | 处理 |
|---|---|---|---|
| ASML 中国区占比 | 29.1%（20-F） | 33%（荷兰议会） | 并列 + 标注两个口径 |
| 中国光刻机进口额 | 106.2 亿美元 | 8.1 亿美元（CEPEA） | 并列 + 说明统计范围差异 |
| 国产化率 | 2.5% | <1% | 并列 + 标注 |

**并列 + 说明差异，比一个漂亮的平均数有用得多。**

### ⚠️ 「看起来新」不等于新

标题语气完全不能用来判断时效。搜狗和 `site:` 都实测捞到过把一年前旧文
当「最新研判」的情况。**必须核 `create_time`。**

### ⚠️ 「看起来像研报」不等于不是软文

账号主体要单独核。实测有账号「纪要研报小组」的文章，正文开头就是知识星球引流。

### ⚠️ 子 agent 会给不存在的 URL

子 agent 在没有实据时会「补」一个看起来合理的链接。所以模板里写死：
**url 必须是实际访问过的原文**；靠搜索摘要拿到的必须标注「摘要获取、未核验原文」。

写死这条之前，报告里确实混进过无法访问的链接。

## 三、验证方法的坑（最值钱的部分）

### ⚠️ 验证脚本本身也会有 bug，而且会「通过」

设计交付前自检时，我写过一个引用对应性检查，正则用的是：

```python
[NJDuct]\d{1,2}          # ← 错
```

本意是匹配「N/J/D/U/C/T 等前缀 + 数字」。但**方括号里是逐字符的字符类**——
`uct` 三个小写字母永远不可能出现在引用 ID 里，等价于只匹配 `N`、`J`、`D`。
它把所有 U/C/T 开头的来源**全部排除在检查之外**。

结果它报出「引用 36 / 附录 36 / 差集为空 ✓」——**看起来很对**。
改用 `[A-Za-z]\d{1,2}` 重跑，真实结果是 **80 引用 ↔ 80 来源**（也是完美 1:1，
但那是运气——两个错误恰好互相抵消了数量）。

> **教训**：**自检工具自己也要被测试。** 一个「检查通过」的报告，
> 可能只是检查本身瞎了。要用**故意构造的错误样例**去验证自检确实会拦下来。

### ⚠️ 短测试给出的结论，和原故障一样不可信

这个坑在本项目里犯了**两次**，方向不同：

**第一次**：结论「真 Chrome 路径无速率限制」来自单次会话 13 组查询。
实际故障在**跨会话累积**尺度才发作。→ 详见 [`02-公众号检索通道.md`](02-公众号检索通道.md)

**第二次**：把旧转换脚本重写成 `build.py` 时，**漏了附录条目的 `id="src-X"` 锚点逻辑**。
内置自检在第一次回归跑时**当场报出全部 80 条来源悬空，并拒绝写文件**。

第二次是**好事**——它说明自检是承重的、真的拦住了。
第一次是坏事——它说明**没被拦住的时候，你也不知道是没问题还是没检查到**。

> 判据：**验证通过的规模，必须 ≥ 已知会触发故障的规模。**
> 不确定触发规模时，先压到远超预期。

### ⚠️ 「断言错了」和「代码错了」长得一样

写转换器回归测试时断言 `body.count('<ul>') == 3`，实测是 5。
第一反应是代码有 bug，实际是**我的断言写错了**（那是 3 层嵌套 + 1 个松散列表 + 附录列表）。

**先看现场，再改代码。** 否则会去「修」一个没坏的东西。

## 四、协作层面的坑

### ⚠️ 格式化输出会被自动链接破坏

`build.py` 的裸 URL 自动链接用了负向后行断言 `(?<!["\'=/>])`，
确保它**不会**重写已经生成在 `href="..."` 属性里的 URL。少了这个断言，
第二次处理会把 `href` 里的链接再包一层。

### ⚠️ 反斜杠转义必须在代码块暂存**之后**处理

行内处理的顺序是有讲究的：

```
暂存代码块/行内代码 → 处理反斜杠转义 → 还原 <br> → 链接 → 强调 → 引用锚点 → 自动链接
```

顺序错了，`\*literal\*` 会被当成斜体渲染。
