# 已知边界与坑

这份文档记录**实际踩过的坑**。大部分不是「代码写错了」，而是
**「验证方式本身在骗人」**——后者隐蔽得多，也更值得写下来。

## 一、`report-html` 转换器的边界

### 支持的语法

ATX 标题 `#`–`######`、围栏代码块、水平线、**嵌套**有序/无序列表 + 松散列表 + 缩进续行、
**嵌套**引用块、表格（含 `:---:` 对齐与单元格内 `<br>`）、
粗体/斜体/删除线/行内代码/反斜杠转义、`[文字](url)` 与裸 URL 自动链接。

特有约定：`[X9]` 形式引用 ID 自动变成跳转锚点；附录里 `- X9 / 标题 / …` 形式的条目
自动获得 `id="src-X9"` 目标。

### 不支持（会原样保留）

setext 标题（`===` 下划线式）、引用式链接、脚注、任务列表、HTML 块、定义列表。

### 边界

| 项 | 说明 |
|---|---|
| **图片降级成链接** | 为保证输出自包含，`![alt](url)` 不渲染远程图片，改为链接 |
| **正文里的字面量 `**` 会误判** | 会被「残留 Markdown」自检拦下。用 `&#42;` 或改写措辞。自检已剔除 `<style>`/`<script>`，所以只影响**可见正文** |
| **只做静态渲染** | 无交互、无搜索框 |
| **需要 python3** | 纯标准库，无第三方包 |
| **宽表格靠横滑** | 见下节：手机上塞不下的表格改为横向滚动 + 提示，不换行折行 |

### 响应式：桌面 / 手机

断点两档——`≤900px` 收起侧边目录、缩小表格字号与内边距；`≤560px` 再压一档正文与标题。

**宽表格的处理**（这是唯一需要取舍的地方）：不折行、不隐藏列，改为**横向滑动 + 视觉提示**。
`build.py` 把每张表包进 `.twrap > .tw`，内联的 JS 在加载/缩放/滚动时实测
`scrollWidth > clientWidth`，**只有真的塞不下**才给容器打 `.scrollable`——
此时右缘出现渐隐、下方出现「← 左右滑动查看 →」；滑到最右端渐隐自动消失。塞得下就一动不动。

> 为什么不用「折行」：把 5 列表格折成手机上的一列，列与列的对应关系就没了，
> 而研报表格的价值恰恰在横向对照。横滑保住了对照关系，代价是需要一次滑动。
> ⚠️ `≤900px` 那档把表格字号和内边距调小了，于是**出现过 960px 有 2 张表溢出、768px 反而 0 张**
> 的非单调现象。这是断点副作用，不是 bug，但改字号时要重新量。

### ⚠️ 列表分支漏调 `restore()` → 链接「凭空消失」

`inline()` 用 `\x00N\x00` 占位符暂存生成好的 HTML（链接、行内代码），最后要 `restore()` 还原。
**段落、标题、表格三条分支都还原了，唯独列表（`_render_tree`）没有。**

潜伏期很长：以前链接是在转义后直接生成的，不走占位符；列表里只有行内代码会漏。
直到为了让 URL 里的 `&`/`*` 不被破坏、把链接也挪进占位符，**附录 80 条来源的 URL 全部变成不可见的 `\x00N\x00`**。

- 修复：在 `convert()` 出口统一 `restore()` 一次（单一收口，比逐分支补更可靠）
- 护栏：自检现在会统计 `\x00\d+\x00` 残留，命中即报错
- ⚠️ **这类故障最坑的地方是它「看起来像修好了」**——见第三节

### ⚠️ headless Chrome 截图不响应锚点跳转

用 `--screenshot file:///...#h16` 想验证某个锚点的渲染，**拿到的是页面顶部**——
headless 模式下锚点跳转不生效。

可行的替代：
- 把目标片段单独抽出来配同一份 CSS 成一个独立 HTML 再截图
- 量化探针改用 `--dump-dom --virtual-time-budget=2000`

## 二、数据判断的坑

### ⚠️ 口径分歧**不要取平均**

同一指标多来源冲突时，取平均是**最糟的处理**——它伪造了一个不存在的精确值。

真实例子（`examples/lithography_深度研报_2026-10-09.md` 里就有三处）：

| 指标 | 来源 A | 来源 B | 处理 |
|---|---|---|---|
| ASML 中国区占比 | 29.1%（20-F） | 33%（荷兰议会） | 并列 + 标注两个口径 |
| 中国光刻机进口额 | 106.2 亿美元 | 8.1 亿美元（CEPEA） | 并列 + 说明统计范围差异 |
| 国产化率 | 2.5% | <1% | 并列 + 标注 |

**并列 + 说明差异，比一个漂亮的平均数有用得多。**

### ⚠️ 「看起来新」不等于新

标题语气完全不能用来判断时效。搜狗和 `site:` 都实测捞到过把一年前旧文
当「最新研判」的情况。**必须核 `create_time`。**

### ⚠️ 「看起来像研报」不等于不是软文

账号主体要单独核。实测有账号「纪要研报小组」的文章，正文开头就是知识星球引流。

### ⚠️ 子 agent 会给不存在的 URL

子 agent 在没有实据时会「补」一个看起来合理的链接。所以模板里写死：
**url 必须是实际访问过的原文**；靠搜索摘要拿到的必须标注「摘要获取、未核验原文」。

写死这条之前，报告里确实混进过无法访问的链接。

## 三、验证方法的坑（最值钱的部分）

### ⚠️ 验证脚本本身也会有 bug，而且会「通过」

设计交付前自检时，我写过一个引用对应性检查，正则用的是：

```python
[NJDuct]\d{1,2}          # ← 错
```

本意是匹配「N/J/D/U/C/T 等前缀 + 数字」。但**方括号里是逐字符的字符类**——
`uct` 三个小写字母永远不可能出现在引用 ID 里，等价于只匹配 `N`、`J`、`D`。
它把所有 U/C/T 开头的来源**全部排除在检查之外**。

结果它报出「引用 36 / 附录 36 / 差集为空 ✓」——**看起来很对**。
改用 `[A-Za-z]\d{1,2}` 重跑，真实结果是 **80 引用 ↔ 80 来源**（也是完美 1:1，
但那是运气——两个错误恰好互相抵消了数量）。

> **教训**：**自检工具自己也要被测试。** 一个「检查通过」的报告，
> 可能只是检查本身瞎了。要用**故意构造的错误样例**去验证自检确实会拦下来。

### ⚠️ 短测试给出的结论，和原故障一样不可信

这个坑在本项目里犯了**两次**，方向不同：

**第一次**：结论「真 Chrome 路径无速率限制」来自单次会话 13 组查询。
实际故障在**跨会话累积**尺度才发作。→ 详见 [`02-公众号检索通道.md`](02-公众号检索通道.md)

**第二次**：把旧转换脚本重写成 `build.py` 时，**漏了附录条目的 `id="src-X"` 锚点逻辑**。
内置自检在第一次回归跑时**当场报出全部 80 条来源悬空，并拒绝写文件**。

第二次是**好事**——它说明自检是承重的、真的拦住了。
第一次是坏事——它说明**没被拦住的时候，你也不知道是没问题还是没检查到**。

> 判据：**验证通过的规模，必须 ≥ 已知会触发故障的规模。**
> 不确定触发规模时，先压到远超预期。

### ⚠️ 「断言错了」和「代码错了」长得一样

写转换器回归测试时断言 `body.count('<ul>') == 3`，实测是 5。
第一反应是代码有 bug，实际是**我的断言写错了**（那是 3 层嵌套 + 1 个松散列表 + 附录列表）。

**先看现场，再改代码。** 否则会去「修」一个没坏的东西。

### ⚠️ 「坏链为 0」和「链接全没了」长得一模一样

这是本项目里**最接近骗过自己**的一次。修完上面那三个链接 bug 后，我写了验证脚本查：

```
被截断的链接（以 & / &amp 结尾）: 0     ← 修之前是 8
```

**这个 0 看起来就是成功。** 实际上此刻附录 80 条来源的 URL **全部变成了占位符**，
一个都没输出——没有链接，自然没有坏链。**我的检查只查了「坏的还在不在」，没查「好的还在不在」。**

是顺手做的一次抽查救了场：搜 `mp.weixin` 在输出里出现几次 —— 源里有 7 条，输出里 **0 次**。

> **判据：验证必须同时查「负向消失」和「正向保留」。**
> 只查前者，一次彻底的删除会和一次成功的修复给出同一个绿灯。
> 具体做法：拿源文件里的**已知好值**（数量、抽样原文）去比对输出，而不是只数错误。

同一个 0 陷阱还有第二个入口：我第一版验证脚本用 `2>/dev/null` 吞掉了 stderr，
而 `--dump-dom` 会把 `>` 转义成 `&gt;`，正则匹配不上，四个宽度全部返回「无结果」——
**看起来像是「没有溢出」，实际是「没有测量」。** 探针必须能自证它跑起来了。

## 四、协作层面的坑

### ⚠️ 格式化输出会被自动链接破坏

`build.py` 的裸 URL 自动链接用了负向后行断言 `(?<!["\'=/>])`，
确保它**不会**重写已经生成在 `href="..."` 属性里的 URL。少了这个断言，
第二次处理会把 `href` 里的链接再包一层。

### ⚠️ `inline()` 的处理顺序是承重的

```
<br> 暂存 → 行内代码暂存 → 反斜杠转义暂存 → 【链接 + 裸 URL】 → html.escape
         → 还原 <br> → 删除线 → 粗体 → 斜体 → 引用锚点
```

两个关键约束：

1. **反斜杠转义必须在代码块暂存之后**，否则 `\*literal\*` 会被当成斜体。
2. **链接提取必须在 `html.escape` 之前**（这一条是血的代价，见下）。

### ⚠️ 链接提取晚于 `html.escape` → 三个 bug 一起发作

原来链接是在 `html.escape` **之后**用正则提取的，结果：

| 症状 | 机理 |
|---|---|
| **带查询参数的 URL 全被截断**（实测 8/13） | `&` 先变成 `&amp;`，而裸 URL 的终止符集合包含 `;`，于是在第一个 `&amp;` 处切断 → 发布出去的 href 是 `https://mp.weixin.qq.com/s?src=11&amp` |
| **URL 里的 `*` 被强调解析吃掉** | 公众号 `signature` 参数自带 `*`，被 `*...*` 规则切成 `<em>` |
| **行内代码二次转义** | `_keep()` 从**已转义**的字符串里取值，再转义一次 → `&amp;amp;` |

修复：把链接提取（`[文字](url)` 与裸 URL）整体移到 `html.escape` **之前**，
新增 `_link()` 自行转义并暂存——生成后的 `<a>` 不再参与任何后续解析。
