# 行业调研助手 · 审查与质控机制调研报告

> 状态：调研初稿（基于 web 检索与领域知识整理）
> 日期：2025-08

## 1. 问题界定

AI 调研报告的核心质量风险：**幻觉（编造事实/数据）、引用失真（引用与内容不符）、数据口径混乱、来源不可信、信息过时、立场偏差、提示注入（被网页内容劫持）**。
审查机制的目标不是"零幻觉"（不现实），而是**让每一条关键结论可追溯、可复核、风险可见**。

## 2. 幻觉抑制（Hallucination Mitigation）

| 手段 | 做法 | 成本 | 效果 |
|------|------|------|------|
| RAG 接地 | 生成必须基于检索到的证据卡，禁止凭空输出 | 低（架构要求） | ★★★★★ |
| 强制引用 | 每个关键数据点/结论后必须内联引用 [n]，引用必须真实存在于证据卡 | 低 | ★★★★★ |
| 证据不足即标注 | 检索不到支撑时写"无公开权威数据/各方说法不一"，而非编数字 | 低 | ★★★★ |
| 置信度标注 | 对数据点标来源等级（官方/媒体/自媒体）与时效 | 中 | ★★★★ |
| 检索再生成（RAG 迭代） | 生成中发现自己缺依据时触发补充检索 | 中 | ★★★★ |

**关键设计**：写作智能体的 prompt 中硬性规定"每个数字必须来自证据卡，来源未命中则留空并触发补充检索"。这是成本最低、效果最直接的防线。

## 3. 事实核查（Fact-Checking）

### 3.1 核查流水线

```
报告草稿 → 抽取主张(claim extraction) → 检索证据(evidence retrieval)
→ 证据比对判定(支持/矛盾/无证据) → 标注+修正 → 核查报告
```

### 3.2 工具与方法

| 方法/工具 | 说明 | 适用阶段 |
|-----------|------|----------|
| FacTool / FactTool 类开源框架 | 主张抽取 + 检索 + 判定（GPT-Researcher 社区有类似尝试） | 成稿后 |
| 自建「证据卡比对」核查器 | 用证据卡库做 LLM 判定：主张 vs 证据（支持/矛盾/无证据） | 成稿后，推荐 |
| Self-consistency（多次采样一致性） | 同一问题多次生成，分歧大处标记 | 生成中 |
| LLM-as-judge（独立审查智能体） | 用与写作不同的模型/prompt 评审 | 成稿后 |
| 多模型交叉验证 | DeepSeek 写 + Claude/Qwen 审（不同模型盲区不同） | 关键报告 |
| Google Fact Check API / Snopes 等 | 公开事实核查库 | 通用事实 |
| 数字专项核查 | 对报告内所有数字做"来源命中检查"（数字必须能在证据卡中找到） | **行业数据报告必做** |

## 4. 引用与来源验证

| 检查项 | 自动化手段 |
|--------|-----------|
| 链接有效性 | 逐条请求 URL（HEAD/状态码），404/超时标记 |
| 内容匹配 | 用证据卡 hash 对比原文，确认引用未张冠李戴（用抽取的原文片段比对） |
| 来源权威性 | 域名/机构白名单打分（官方 > 交易所 > 主流媒体 > 自媒体） |
| 时效性 | 数据年份与"报告发布日"对比，超期数据标记 |
| 多源一致 | 同一指标多源比对，不一致标记并让审查员裁决 |

**关键设计**：证据卡是引用验证的锚点——**没有证据卡的引用一律视为无效引用**，这是把"引用"从装饰变成硬约束的核心机制。

## 5. 数据交叉验证（行业数据专项）

行业报告里的市场规模/增速/市占率是最容易出问题的地方：

1. **官方基准校验**：先取国家统计局/行业协会/交易所数据为基准。
2. **三角验证**：同一指标至少两个独立来源（如招股书 vs 咨询机构 vs 官方统计）。
3. **异常值检测**：增速/占比偏离常识区间（如年增速>100% 或为负且无解释）自动标记。
4. **口径记录**：每个数据点记录口径（含/不含、统计范围、时点），口径不同不算矛盾，但必须标注。
5. **预测 vs 事实区分**：研报预测必须标注"预测/观点"，不得与事实混排。

## 6. 人工审核（Human-in-the-Loop）

纯自动化无法兜底，**人必须在关键节点把关**：

| 节点 | 人工做什么 | 自动化辅助 |
|------|-----------|-----------|
| 大纲评审 | 确认调研方向、覆盖范围 | 自动生成大纲草案 |
| 证据卡抽查 | 抽查关键数据的证据是否真实 | 自动高亮"高风险证据卡"（无官方来源/单源） |
| 成稿审阅 | 通读、批注、否决 | 自动生成"风险清单"（矛盾点/无证据结论/失效引用） |
| 发布门 | 签字放行 | 未通过检查项的报告禁止标记"已发布" |

**关键设计**：所有中间产物（大纲、证据卡、数据表、草稿、核查报告）都落盘为可审阅文件，并且**支持批注回流**（人改一处，系统记录差异，形成反馈闭环用于后续生成）。

## 7. 评估框架与测试集

| 工具 | 用途 | 备注 |
|------|------|------|
| **RAGAS** | 检索质量（忠实度/相关性/上下文精度） | 开源，中文友好 |
| **DeepEval** | 端到端评估 + 回归测试 | 开源，可接入 CI |
| **TruLens** | RAG 质量追踪 | 可观测性 |
| **G-Eval** | LLM 按 rubric 打分 | 通用 |
| **自建 golden 集** | 领域专属问答 + 已知事实核对集 | **行业调研最该投资的部分** |

**建议**：建立「行业调研评估集」——对每个重点行业预置 20-50 条 golden 问答（答案来自权威源），每次流水线改动后跑回归，防止"修 A 坏 B"。

## 8. 对抗与安全

| 风险 | 应对 |
|------|------|
| 网页提示注入（检索内容劫持 LLM） | 检索文本与指令分离（用结构化数据包裹，禁止把网页原文当指令）；对可疑内容（如"忽略以上指令"）过滤 |
| 假新闻/AI 生成假报告冒充权威 | 信源白名单 + 域名校验 + 权威源优先排序 |
| 垃圾内容污染知识库 | 入库前质量过滤（长度、来源等级、重复率） |
| 恶意查询（诱导系统泄露其他报告） | 权限与审计；单租户 MVP 阶段风险低 |

## 10. 推荐的分阶段审查流程（落地）

| 阶段 | 自动化检查 | 人工介入 | 成本 |
|------|-----------|----------|------|
| 检索阶段 | 信源等级过滤、去重、质量门 | 无 | 低 |
| 抽取阶段 | 证据卡 schema 校验、来源命中检查 | 抽查 | 低 |
| 成稿阶段 | ①引用有效性（URL+内容匹配）②数字来源命中 ③多源矛盾检测 ④LLM-as-judge 一致性 | 高风险项复核 | 中 |
| 发布阶段 | 检查项全绿 → 允许标记发布；免责声明注入 | **终审签字** | 中 |
| 持续 | 评估集回归测试（RAGAS/DeepEval + golden 集） | 定期人工抽检 | 低 |

> 成本估算：自动化检查约占单份报告 20-40% 的 token 成本；人工审阅约 10-30 分钟/份。
> 原则：**自动化负责"让问题暴露"，人工负责"对关键问题裁决"**。
