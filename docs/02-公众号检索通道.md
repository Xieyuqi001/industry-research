# 公众号检索通道

微信公众号是**围墙花园**——普通搜索引擎索引不到，必须显式指定站内搜索。
但它是中文行业信息里密度最高的免费来源之一，值得单独为它搭一条链路。

> ⚠️ **本通道只在「完整深度」档位启用**，且需要用户开着 Chrome。
> 快速概览档位跳过整个公众号检索。

## 三层链路

```
① 搜索   真实 Chrome → https://weixin.sogou.com/weixin?type=2&query={关键词}
              ↓  解析 <a id="sogou_vr_11002601_title_N">
② 解析   页面内同步 XHR 拉 /link?url=... → 从 `url += '...'` 拼串还原真链
              ↓
③ 读取   curl + 浏览器 UA → 正文在 id="js_content"
```

### ① 搜索

```
https://weixin.sogou.com/weixin?type=2&s_from=input&query={关键词}&ie=utf8&page=1
```

解析结果锚点 `<a href="..." id="sogou_vr_11002601_title_N">`。
⚠️ **`href` 属性在 `id` 属性前面**，正则别写反。

### ② 解析真链

结果里的 `href` 是 `/link?url=...` 跳转形式，页面里用 JS 拼串还原：

```js
url += '...'   // 逐段抠出拼接
```

⚠️ **必须有 `Referer` = 搜索页**，直接开 `/link` 会被打去 antispider。

⚠️ 现在返回的拼串**已含完整 `https://mp.weixin.qq.com/...`**，
不要再补 `https://mp.` 前缀（会变成 `mp.https://mp.`）。判断：以 `http` 开头就直接用。

**性能要点**：在同页用**同步 XHR**（`x.open('GET', h, false)`）批量拉 `/link`，
一次调用解析完 10 条；比逐条 `location.href` 导航快两个数量级（后者 8 秒/条）。

**AppleScript 转义要点**：JS 里刻意**不用任何反斜杠转义**，用 `String.fromCharCode(39)` 造引号，
躲开 AppleScript + bash 双重转义的坑。

### ③ 读取

拿到的真链（`/s?src=11&timestamp=...&signature=...` 形式）用 `curl` 直接可读，
与平时抓 `mp.weixin.qq.com` 一样抽 `js_content`。

## ⚠️ 请求指纹门禁

搜狗对**请求指纹**有门禁，不是 IP 限流：

| 请求方 | 结果 |
|---|---|
| 真实 Chrome | `anchors=10 / anti=false` ✅ |
| `curl` | 302 → `weixin.sogou.com/antispider/?antip=wx_sh2` ❌ |
| `curl_cffi`（6 种 impersonate + 预热 cookie） | 同样 302 ❌ |

同一时刻、同一 IP 对照测试 —— **所以既不是 IP 限流，也不是 cookie 问题**。

`curl` 初期能过约 **3 次**，之后被标记，且**不会随时间恢复**（等 60 秒、换新 cookie jar 均无效）。

## ⚠️ 验证码：真实 Chrome 也会被风控

**这不是「Chrome 就安全」。** 真实 Chrome 在**累计查询量**达到阈值后同样会弹人机验证码。

与 curl 那条路的关键区别：

| | curl 被标记 | Chrome 验证码 |
|---|---|---|
| 触发条件 | 约 3 次后 | 累计查询量达阈值 |
| 是否恢复 | **不恢复** | **人工过一次后恢复** |
| 性质 | 永久标记 | 会话/累计计数 |

**未知项（未复现，不要假装知道）**：阈值具体多少、窗口多长（按天还是按小时）、
按 IP 还是按浏览器 profile、验证通过后计数是否清零。
—— 复现一次要再触发一次验证码、代价是用户手动过一次，所以**没有复现**，
也就**不声称这个问题「已解决」**，只做了降级保护。

### 一个真实教训

早期结论是「真 Chrome 路径无速率限制（实测一口气 5/5 全成）」——**这个结论是错的**。
它来自**单次会话 13 组查询**。故障在**跨会话累积**尺度才发作。

> 「刚跑完一轮没事」**证明不了**安全。短测试会给你一个明确但完全错误的结论。

### 一个真实的 bug（已修）

脚本原来写的是：

```js
if (!as.length) return 'NO-RESULT';   // ← 错
```

而**验证码页同样没有结果锚点** → 验证码被误报成 `NO-RESULT`，
而 skill 对 `NO-RESULT` 的规定是「重跑一次」→
**在最不该重试的时刻自动重试验证码页**。

现在改为先判 `CAPTCHA`（URL 含 `antispider` / 标题或正文含 验证·拖动·滑块），与 `NO-RESULT` 分流。

## 保护措施（中等力度）

| 措施 | 值 |
|---|---|
| 单次研报查询数上限 | `1 + N`（N = 国家数） |
| 查询组间隔 | `sleep 12` |
| `NO-RESULT` | 只重试 1 次，仍失败则跳过该查询、继续下一组 |
| `CAPTCHA` | **立即熔断整轮**搜狗检索 |

### 两种「不可用」的处置完全不同

- **`CAPTCHA`** = 搜狗弹了人机验证页。**这是硬熔断信号**：
  立刻停止本轮**所有**剩余搜狗查询，**不要重试、不要换个查询词再试**。
- **`NO-RESULT`** = 那一刻搜索页本身被软拦（不是渠道失效）：
  重试一次；仍不行就跳过该查询。**别把它当 `CAPTCHA` 去熔断整轮。**

### 熔断后怎么收尾

**已知国家照发，缺的走 `site:`**：

1. **已经搜到的国家池照常分发**给对应子 agent（别丢弃已拿到的成果）
2. **还没搜到的国家**改用 `site:mp.weixin.qq.com {行业关键词} {国别词}` 回退（召回 1–5 条）
3. **在报告末尾如实披露**哪几国走了弱通道

⚠️ **别在同一行业上反复重跑检索**——验证码是累计查询量触发的，同一天内多次跑完整深度会叠加。

## 按国别分池（重要修正）

**最初的写法把公众号当成「中国专属来源」，这是错的。**

错在混淆了**平台语言 ≠ 信息主体的国别**：中文公众号大量报道台湾、日本、韩国、美欧产业。

现在的做法：

| 查询形式 | 进哪个池 |
|---|---|
| 泛查询（`固态电池`） | 中国池 |
| `行业词 + 国别词`（`固态电池 韩国`） | 韩国池 |

实测**国别相关性接近 100%** —— 加国别词能把池子干净地按国别切开。
「欧洲」「台湾」都能直接当国别词（欧洲返回欧盟层面 + 荷兰德国的内容；
台湾返回台积电、台湾设备市场，无政治噪声）。

⚠️ **代价：加国别词 = 拿时效换相关性。** 泛词在热点行业能拿到当天文，
加国别词后最新常是几个月到几年前。见 [`01-资料渠道.md`](01-资料渠道.md) 的时效分级。

## 实测数据

### 时效随话题差异极大（3 组关键词 × 10 条）

| 话题 | 时效 |
|---|---|
| 热点话题（当日有新闻） | 6/6 全是当天～1 天 |
| 泛话题（「光伏产能过剩」「创新药出海」） | 中位数 **270 天**；11/24 超一年；最旧 **1618 天** |

整体：一周内 6/24（25%）、一年以上 11/24（46%）。
规律是**新鲜的和权威的常常是两拨人**——热点话题多是券商/自媒体号（新但轻），
泛话题多是财新、中国新闻周刊这类主流媒体（重但旧）。

### 「行业词+国别词」路由（9 组查询 × 10 条）

| 查询 | 最新一条 | 90 天内 | 国别相关性 |
|---|---|---|---|
| 固态电池（热点·泛词） | 当天 | 10/10 | 中国 |
| 固态电池 韩国 | 4 天前 | 1/10 | ✓ 主体韩国 |
| 固态电池 日本 | 2026-03 | 0/10 | ✓ 主体日本 |
| 半导体设备 美国 | 2024-04 | 0/10 | ✓ 主体美国 |
| 半导体设备 台湾 | 2023-06 | 0/10 | ✓ 主体台湾 |
| 光伏 + 美国/日本/欧洲 | 2024-03～06 | 0/10 | ✓ 各自主体 |

### 日期可以免费拿到

搜狗结果页每条 `span.s2` 里含 `timeConvert('<unix秒>')`，直接换算，
**不用额外抓正文**（实测与正文 `create_time` 完全一致）。
所以**在交给子 agent 之前就能按日期筛**。

## 未采用 / 存疑

- **`fancyboi999/weixin_search_mcp`**（GitHub，无 LICENSE）走的是同一套搜狗链路：
  硬编码 cookie（早已过期）+ `url +=` 拼串。**读思路可以，代码别抄**；
  且它的 `_is_antispider_response` 会静默返回空——**失败会被伪装成「没搜到」**。
- **ima 知识库**：能检索到公众号文章（连微信号都给），但 URL 挂在 JS 点击处理器上，
  必须**真实点击**才开新标签；程序化 `.click()` 和全套合成事件都无效
  （`window.open` 只认 `isTrusted:true`）。搜狗是 `location.href` 同标签导航，
  脚本可直接驱动、**无需人工**，所以选搜狗。
- 极速数据公众号搜索 API（jisuapi.com）——付费接口，未评估。
