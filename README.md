# industry-research

> 一套 Claude Code skill：**输入一个行业名，产出一份带可追溯来源的跨国行业研究报告，
> 并自动生成可直接阅读的网页版。**

## 它做什么

对任意行业，产出一份六节的报告：

1. **行业界定** —— 含什么、不含什么
2. **全球产业链地图** —— 全球总量锚点、国别识别与角色、供应链依赖关系
3. **分国别深潜** —— 每个重点国家的角色/公司/数据/估值/政策/格局
4. **全球竞争格局与估值对标** —— 跨国横向对比
5. **关键标的** —— 按上市地归类
6. **风险提示**

加「资料来源」附录。**正文每个数字都带内联引用，与附录一一对应。**

## 快速开始

需要 **Claude Code** 和 **python3**（纯标准库，无第三方依赖）。

```bash
git clone https://github.com/Xieyuqi001/industry-research.git
cd industry-research
./install.sh
```

`install.sh` 会把两个 skill 复制到 `~/.claude/skills/`；
若已存在同名 skill，会先加时间戳备份，不会静默覆盖。

装完后在 Claude Code 里直接说：

```
帮我看看光伏行业
```

它会先问你两件事（**是否要完整研报**、**市场范围与深度档位**），确认后才开始检索。

### 只想用网页转换

`report-html` 跟行业无关，任何 Markdown 长文档都能用：

```bash
python3 ~/.claude/skills/report-html/build.py 你的文档.md
```

产出同名 `.html`：单文件自包含、零外部请求，断网可开、拷给别人不丢样式。
`Cmd+P` 直接转 PDF。

## 设计要点

### 判断留给模型，纪律写成 skill

绝大多数复杂度不在「检索基础设施」，而在**判断**：哪个数字口径可信、
这条来源是研报还是软文、同一指标两个来源给了不同值该怎么办。

所以终态不是一套框架，而是**把流程和验收标准写成 skill，让模型执行**。
代价是**没有确定性保证**——同一行业跑两次，来源数量和措辞会不同。
换来的是零基础设施、零依赖、一个下午能改。

### 检索上收到主 agent，子 agent 只读

子 agent 并行跑，如果每个都去搜，会**同时**撞上公众号通道的限流和验证码，
而且互相看不见对方在搜什么，必然重复。

所以检索由主 agent 串行做（可控限流 + 单点熔断），子 agent 只负责读和判断。
这条分工是实测逼出来的，不是设计洁癖。

### 自检不合格就不落盘

`report-html` 在写出前会检查**悬空引用**（正文引了 `[X9]` 但附录没这条）、
残留未转换的 Markdown、输出是否真的自包含。**不过就不写文件**——
它不会产出「看起来成了、其实引用全断」的页面。

行业报告也有 8 项交付前自检，其中**跨章节一致**（跨国对比的数字与国家章节里的同源数字不矛盾）
和**引用↔附录一一对应**是返工率最高的两项。

## 已知边界

这套东西是**能用**，不是**可靠**。诚实列出：

| 边界 | 说明 |
|---|---|
| 输出不确定 | 同行业跑两次结果不同，来源数量会浮动 |
| 依赖 Claude Code | 是 skill，不是独立程序 |
| 公众号通道要真实浏览器 | 且**累计查询量过阈值会弹人机验证码**，需人工过一次 |
| **阈值未知** | 触发阈值/窗口/是否按 IP 都**未复现**，只做了降级保护，不声称已解决 |
| 部分来源拿不到 | 公众号付费文、GBK 编码财经站、墙外站 |
| 图片降级 | 转换器为保证自包含，`![图](url)` 渲染成链接 |
| 非中国来源常偏旧 | 中文报道外国行业本就少且旧，是供给约束，换查询写法也拿不到新的 |

详见 [已知边界与坑](docs/03-已知边界与坑.md)。
